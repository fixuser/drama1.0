# 90 明确排除项

## 1. 排除原则

2.0 从空库发布，因此“排除”不是隐藏页面或保留只读兼容，而是从新系统中完全不存在。一个排除项必须同时满足：

1. 无公共端和管理端入口、Proto、HTTP 路由或内部 RPC；
2. 无表、字段、枚举、索引、迁移、种子数据或历史读取器；
3. 无配置、缓存键、消息消费者、定时任务、领域订阅或通知跳转；
4. 不进入订单、资产流水、收益、任务、等级、团队或统计白名单；
5. 未知旧请求只得到标准未找到/不支持错误，不产生任何事实；
6. 不为“未来可能恢复”预留通用抽象或运行时开关。

## 3. 活动族完整清单

下列名称及其别名均不进入 2.0：VIP Invite/Worship、pilgrimage、FlashSale、AI-X subscription、AI/超级嘉年华、mega/super subsidy、upgrade/help subsidy、lottery、Ramadan/TeamRoom/GroupBuy、treasure plan/Pool Hadiah、33 Invite/Challenge/Cooperation、anniversary、support bonus、deposit bonus/match、double wages、recharge double gift、活动合伙人页面和活动机器人机会。

任何新发现的 1.0 功能只要依赖限时资格、抽奖、额外赠送或活动奖池，默认排除；若确需进入 2.0，必须独立产品决策和 ADR，而不是恢复旧分支。

## 4. 不允许出现的 Schema/枚举

- 资产类型不得出现支持值、活动币、bonus、gift、double 等成员。
- 等级枚举不得出现旧 `FREE/VIP/ONE...SIX` 名称或转换表。
- 订单类型不得出现 auto payment、subscription、copyright、marketing pack、activity、TaskPlan。
- 券表和券枚举只允许 `Robot Activation Voucher`；不建立一个可承载所有券种的通用券大表。
- 用户表不得出现 F 码、字符串祖先链、活动计数、聊天身份、版权状态或资金余额列。
- 新表不得带 `legacy_*`、`old_*`、`migration_*`、`compat_*` 字段。

| 剧集购买 | EXPERIENCE 优先、COMMON 补差、权益、COMMON 部分最多两层冻结返佣 | 支持值、活动电影票、版权包 |

## 6. API 行为

- 新系统不注册旧路由；网关返回普通 404/UNIMPLEMENTED，不返回“功能已关闭”的兼容响应。
- 新系统的 Gateway/OpenAPI 路由不得含路径参数；GET 标识放 query，POST 标识放 Proto body，callback 只有固定字面量路由。
- Proto 不认识旧枚举；收到未知数字输入返回 `INVALID_ARGUMENT`，不能降级为其他类型。
- Banner、通知、任务配置和管理菜单的目标白名单不能引用排除路径。
- 导入/管理 API 不允许借“资产调整”“自定义任务”“自定义跳转”重新创建排除能力。

## 7. 静态与运行时防线

CI 使用精确标识符和路径清单扫描 Proto、迁移、Go 注册、配置模板、定时任务和前端契约。中文文档可在本章讨论排除词，因此文档扫描采用白名单；实现目录不得命中。

运行时指标为排除的订单类型、资产类型、收益类型、任务 code、路由和作业名建立零基线告警。由于新库没有历史数据，任何命中都必须阻断发布或立即回滚。

## 8. 验收用例

1. 从空库完成全部迁移后，Schema/枚举中没有本章排除模型和兼容字段。
2. 枚举所有网关路由和 gRPC descriptors，仅存在 `/v2` 与已批准能力。
3. 对旧路径、旧 RPC、旧枚举和 F 码参数做负向调用，不创建订单、资产、关系、任务或审计外业务数据。
4. 完成注册、KYC、充值、VIP、剧集购买、`Playlet Backing`、`Robot Purchase`、升级和提现，不产生任何活动或支持值事实。
5. 等待完整日、周、月作业周期，排除任务/消费者执行数始终为零。
6. 收益和运营报表的类型白名单不含排除项，未知类型触发失败/告警而非归入“其他”。
7. Banner/通知的安全跳转无法发布到排除页面。
8. 代码搜索和依赖图证明没有旧库客户端、双写、历史导入和通用 Outbox。
