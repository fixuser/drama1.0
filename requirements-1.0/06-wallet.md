# 06 钱包

## 1. 业务目标与入口

钱包是所有保留业务的资产视图和记账入口，负责余额、消费币、支持值、活跃值、冻结资产、兑换和流水展示。用户入口为 `/wallet`、`/wallet/details/*`、`/wallet/frozen`、`/wallet/exchange`；运营和财务通过管理端用户资产、流水、订单与提现页面审计。

钱包不得自行创造收益规则；它只执行经业务单据授权的资产变更并提供可追溯流水。

## 2. 资产定义

| 资产 | 服务端含义 | 可用场景 | 是否可直接提现 |
| --- | --- | --- | --- |
| 通用币 `COMMON` | 用户主要可用余额 `AvailablePoint` | 剧集、短剧支持、机器人支持及提现 | 是，受提现规则约束 |
| 消费币 `CONSUME` | 仅消费用途 `ConsumePoint` | 剧集等允许的消费，可与通用币混合 | 否 |
| 支持值 | 支持专用资产，历史命名含 `EmpiricValue` | 短剧支持、与通用币双向转换（按配置） | 否，需按规则转换 |
| 活跃值 | 支持等级和团队资格指标 `ActiveValue` | 等级、额度、合伙人统计 | 否；不是货币 |
| 冻结通用币/收益 | 尚未满足解冻条件的返佣、机器人收益或提现冻结 | 到期解冻、提现终态 | 否，解冻后才可用 |
| 法币余额 `Balance` | 历史/特定结算字段 | 仅按现有合法路径展示 | 是否继续使用待确认 |

**术语要求：**页面必须区分支持值与活跃值；活跃值不可显示为可消费余额。

## 3. 资产总览

现状 `/v1/asset/overview/get` 返回通用币、消费币、冻结资产、法币余额、活跃值、支持值、今日/累计收益、持仓和提现广播等聚合信息。

目标1.0：

- 每个值携带资产类型、精度、更新时间和是否可用；总资产不把活跃值与货币相加。
- “今日/累计收益”只引用净化后的保留收益口径，见 [07-income-statistics.md](07-income-statistics.md)。
- 总览缓存只能用于展示，任何扣款、提现和资格判断必须读取强一致账户数据。
- H5隐藏的排除功能不应继续请求其余额或提示接口。

## 4. 钱包流水

### 4.1 流水最小字段

每笔资产变化应包含：流水ID、用户、资产类型、业务类型、正负金额、变更前余额、变更后余额、关联对象类型/ID、幂等键、业务时间、入账时间和备注/规则版本。

### 4.2 保留业务分类

| 分类 | 典型流水 |
| --- | --- |
| 充值 | 通用币充值原始金额；不再包含 `giveaway` |
| 内容消费 | 剧集通用币支出、消费币支出、混合支付 |
| 一次性VIP | 订单、有效权益及合法历史返佣 |
| 短剧支持 | 支持支出、支持值转出、直接收益、团队返佣、到期处理 |
| 机器人支持 | 支持支出、直接收益、团队返佣、冻结/解冻、到期返本 |
| 合伙人 | 月度分红入账 |
| 任务 | 保留任务奖励 |
| 兑换 | 消费币转通用币、通用币与支持值互转及手续费 |
| 提现 | 冻结、手续费、成功扣减、失败/拒绝退回 |

活动、版权包、AI聊天奖励、VIP邀请、充值赠送等历史类型只读展示，不再生成，且不进入目标收益总计。

## 5. 兑换规则

### 5.1 消费币转通用币

现状公式：`获得通用币 = 消费币数量 ÷ RateConsumeToCommon`。

流程：

1. 服务端校验数量大于0、精度、余额和汇率配置有效；
2. 在账户锁/事务内扣消费币、加通用币；
3. 分别写消费币转出和通用币转入流水，使用相同业务单号；
4. 返回两种新余额。

目标必须明确是否允许反向转换；当前该接口只表示消费币转通用币。

### 5.2 通用币与支持值

- 换入、换出比例和手续费来自 `TipsParameter`/财富参数。
- 公式应在服务端响应中返回拆分：输入、汇率、手续费、净到账。
- 手续费必须有独立流水，不能只从净额反推。
- 换回通用币后才可能提现；兑换本身不应产生收益或活跃值。

## 6. 冻结与解冻

```text
可用余额 --冻结--> 可用减少 + 冻结增加 + 冻结流水(FROZEN)
冻结 --条件满足--> 冻结减少 + 可用增加/正式入账 + 状态(UNFROZEN)
冻结 --业务失败--> 冻结减少 + 可用原路退回 + 状态(CANCELED/FAILED)
```

场景包括剧集返佣、机器人收益、提现。目标要求：

- 冻结记录必须指向来源业务单并保存预计解冻时间；
- 状态迁移采用条件更新，重复任务不重复解冻；
- 账户字段与未终结冻结明细每日对账；
- 提现冻结与收益冻结不得用同一模糊类型展示。

## 7. 主业务资产矩阵

| 业务动作 | 借方/减少 | 贷方/增加 | 失败回滚 |
| --- | --- | --- | --- |
| 充值成功 | 外部支付订单 | 通用币 | 回调失败保持订单待处理，不先入账 |
| 剧集购买 | 消费币优先、再通用币 | 剧集权益 | 任一流水/权益失败全部回滚 |
| 短剧支持 | 通用币或支持值/券 | 支持持仓、可选活跃值 | 扣款、券、持仓、活跃值同事务 |
| 机器人支持 | 通用币 | 持仓、活跃值 | 同事务回滚 |
| 收益/返佣 | 收益业务单 | 通用币或冻结收益 | 以结算唯一键重试 |
| 提现创建 | 可用通用币 | 提现冻结 | 创建失败不冻结；失败/拒绝原路退回 |

## 8. 接口、模型、缓存与任务

接口：

- `/v1/asset/overview/get`
- `/v1/consume/point/exchange`
- `/v1/balance/history/get`
- `/v1/transaction/summary/all/get`
- `/v1/point/ledger/list/v2`
- `/v1/point/frozen/list`
- 支持值兑换接口位于 playlet/user 相关服务，建议后续统一到 wallet 领域

核心模型：`User`资产字段、`PointLedger`、`PointFrozenLedger`、`ActiveValueLedger`、支持值流水、`Order`、`Withdrawal`。

任务：冻结流水每小时解冻、收益/持仓每日处理、统计 rollup 每分钟增量、每日全量对账。缓存包括资产总览、收益总览和排行榜；任何写入后应失效相关用户缓存。

核心证据：

- `splay/services/point/wallet.go`
- `splay/models/point.go`、`splay/models/user.go`
- `splay/apis/basepb/model.proto`、`splay/apis/pointpb/point.proto`
- `h5/src/pages/Wallet/`
- 管理端用户资产、资金流水及财务页面

## 9. 问题、疑问与建议

| 级别 | 类型 | 内容 |
| --- | --- | --- |
| P0 | 建议 | 对所有资产写操作增加金额正数/精度校验、幂等键和余额守恒断言 |
| P1 | 已确认 | `PointLedger` 的收入分组混入大量排除活动类型，钱包总览可能显示被污染收益 |
| P1 | 已确认 | 交易汇总仍将 `PAYMENT_AUTO` 计入VIP，目标需只作为历史兼容数据 |
| P1 | 待确认 | `Balance` 法币余额字段在目标1.0是否仍有合法写入和提现场景 |

| P2 | 建议 | 管理端提供按业务单一键串联订单、持仓、结算、冻结和钱包流水的审计视图 |

## 10. 验收场景

1. 每类保留资产变化都能从钱包流水追到唯一业务单，前后余额相减等于流水金额。
2. 消费币兑换及支持值双向兑换在正常、余额不足、零/负数、超精度和并发下结果正确。
3. 混合购买剧集准确拆分两种资产，消费币部分不产生返佣。
4. 收益冻结、到期解冻和失败退回各执行一次，冻结明细之和等于账户冻结字段。
5. 活动历史流水可查询但不计入目标1.0今日/累计收益，也不能生成新记录。
6. 同一支付回调、结算、领取或提现终态重复执行，钱包只变化一次。
7. 页面明确区分通用币、消费币、支持值、活跃值和冻结资产，不进行无意义合计。
