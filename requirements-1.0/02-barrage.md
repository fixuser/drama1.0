# 02 弹幕

## 1. 业务目标与范围

弹幕是在短剧剧集时间轴上发送、查询和治理的用户内容。虽然接口沿用 `/v1/chat/bullet/*` 命名空间，它与 AI 角色聊天不是同一功能，目标1.0明确保留。

角色与入口：

- 游客/用户：短剧播放页读取弹幕；登录用户可发送、举报、屏蔽单条或屏蔽作者。
- 管理员：弹幕列表、检索和全局隐藏/恢复。
- 任务系统：真实发送行为可推进“发弹幕”任务。

代码入口：`h5/src/pages/Videos/`、`h5/src/apis/chats.ts`；服务端 `splay/services/user/chat.go`；管理端 `splay/services/man/chat.go` 及对应页面。

## 2. 数据对象与状态

| 对象 | 关键字段 | 说明 |
| --- | --- | --- |
| `BulletComment` | 用户、短剧、剧集、播放秒数、内容、语言、全局隐藏、创建时间 | 弹幕正文 |
| `BulletCommentHidden` | 用户、弹幕或作者 | 用户级屏蔽关系 |
| `BulletCommentReport` | 举报人、弹幕、原因、处理状态 | 举报记录 |
| 敏感词配置 | 语言、词语、状态 | 发送时匹配；当前命中后直接隐藏 |

弹幕不使用发布/审核中/驳回的完整状态机。现状等价状态为：正常可见、敏感词命中后全局隐藏、管理员全局隐藏、用户私有屏蔽。

## 3. 发送主流程

1. 登录用户在播放页提交短剧ID、剧集ID、播放秒数和内容。
2. 服务端应校验短剧/剧集存在且匹配、内容长度、时间点在视频时长内、用户状态允许发言。
3. 服务端按当前语言加载启用的敏感词；命中时创建记录但标记全局隐藏。
4. 写入弹幕后，仅由此次真实成功行为推进弹幕任务一次。
5. 返回结果应明确 `visible` 与隐藏原因；当前接口只返回空响应，客户端无法解释命中后的不可见。

**现状差异：**创建代码可确认执行敏感词检测和任务更新，但输入关联、长度、频率及幂等约束在已核对路径中不完整，需进一步运行验证。

## 4. 查询与可见性

### 4.1 现状

- 按语言和剧集查询最新 150 条。
- 全局隐藏弹幕仅作者自己仍可看到。
- 再过滤当前用户已屏蔽的弹幕或作者。
- `Total` 在用户级过滤前计算，因此可能大于实际返回条数。
- H5在播放器时间轴展示，用户端 API 封装未发现举报接口映射，但 Proto 和服务端已存在举报 RPC。

### 4.2 目标1.0

- 查询必须按确定排序返回，支持游标；`total` 应表示过滤后可见数，或字段明确命名为 `unfiltered_total`。
- 匿名用户不能获得被全局隐藏的内容。
- 作者查看自己被隐藏的弹幕时应显示“仅自己可见/审核隐藏”提示。
- 语言缺失时采用短剧或客户端默认语言，记录中保留发送时语言。

可见性规则：

```text
管理员全局隐藏或敏感词隐藏
  ├─ 作者：可见但标识仅自己可见
  └─ 其他人：不可见
用户屏蔽弹幕/作者
  └─ 仅影响该用户，不改变全局状态
```

## 5. 举报与审核

### 5.1 举报

1. 登录用户选择原因并提交弹幕ID。
2. 不允许举报自己的弹幕。
3. 用户可选择只隐藏该条，或同时隐藏作者；两种动作与举报记录在同一事务。
4. 相同用户对同一弹幕的重复举报应幂等，不能无限新增相同记录。

### 5.2 管理审核

**现状：**管理端可列表和切换全局隐藏，但未发现举报队列、原因、处理人、处理结论及审计闭环；举报模型有处理状态但管理 RPC 未完整暴露。

**目标1.0：**

- 待处理举报按次数、原因、最近时间聚合；管理员可通过、驳回、隐藏弹幕、限制作者。
- 记录处理人、处理时间、备注和状态变更审计。
- 恢复全局可见不应删除用户自己的屏蔽关系。

## 6. 任务联动

弹幕任务的唯一有效进度来源应是用户成功创建一条符合规则的弹幕。当前存在两条越权路径：

- 创建机器人支持时，代码循环调用任务更新以直接填满弹幕任务。
- 每日 `checkRobotBarrageTask` 在 12:00 自动完成机器人用户的弹幕任务。

这会让“发弹幕”任务与真实行为脱钩。目标1.0应移除这两种联动；如果业务要奖励机器人持有人，应建立独立任务类型和可解释条件。

## 7. 异常、边界和非功能要求

- 空内容、超长内容、非法时间点、短剧与剧集不匹配：拒绝且不推进任务。
- 重复点击：可用客户端请求ID或短时间内容指纹幂等。
- 频率限制：建议用户维度与IP维度双限流，并记录被限流指标。
- 敏感词服务/缓存异常：采用明确降级策略；不能静默绕过且无告警。
- 已注销/禁用用户历史弹幕保留审计，可统一匿名化作者展示。
- 删除/下架剧集后弹幕不再面向用户查询，管理端仍可审计。
- 举报并发：唯一键建议为 `(reporter_user_id, comment_id)`，重复请求返回已有结果。

## 8. 接口、缓存和配置

保留接口：

- `POST /v1/chat/bullet/comment/create`
- `GET /v1/chat/bullet/comment/list`
- `POST /v1/chat/bullet/comment/report`
- 管理端弹幕列表与全局隐藏更新接口

建议改名影响：长期可增加 `/v1/playlet/barrage/*` 别名，原 `/v1/chat/bullet/*` 在兼容期保留，不直接改 Proto wire 路径。

依赖：语言敏感词配置及其缓存、用户任务更新、短剧/剧集主数据。管理端菜单当前复用了版权包权限标识，属于排除功能耦合，应改为独立 `barrage:*` 权限。

核心证据：

- `splay/apis/userpb/user.proto`：`CreateBulletComment`、`ListBulletComment`、`ReportBulletComment`
- `splay/services/user/chat.go`
- `splay/services/man/chat.go`
- `splay/models/chat.go`
- `splay/services/playlet/tips.go`、`splay/services/playlet/cron.go`：机器人任务联动
- `h5/src/pages/Videos/`、`h5/src/apis/chats.ts`

## 9. 问题、疑问与建议

| 级别 | 类型 | 内容 |
| --- | --- | --- |
| P1 | 已确认 | 查询 `Total` 在用户屏蔽过滤前计算，与返回数量不一致 |
| P1 | 已确认 | 举报缺少管理端审核闭环，用户端 API 封装也未暴露举报调用 |
| P1 | 已确认 | 机器人购买/定时任务可以在没有真实弹幕时完成弹幕任务 |
| P1 | 需验证 | 未发现数据库唯一约束阻止同一用户重复举报同一弹幕 |
| P1 | 需验证 | 发送频率、内容长度、剧集关联和时间点的服务端校验是否由中间件/Proto补充 |
| P2 | 建议 | 敏感词命中记录规则版本和命中类别，避免直接保存或展示具体敏感文本 |
| P2 | 建议 | 增加审核时延、举报命中率、隐藏率和限流率指标 |

待业务确认：敏感词命中后是“保存但仅自己可见”、直接拒绝，还是进入审核队列；作者是否可删除自己的弹幕；屏蔽作者是否跨剧集长期生效。

## 10. 验收场景

1. 正常弹幕在正确时间点展示，并只推进一次弹幕任务。
2. 命中敏感词后其他用户不可见，作者得到明确状态，管理员可查询与处理。
3. 屏蔽单条和屏蔽作者只影响当前用户；恢复全局状态不清除个人屏蔽。
4. 举报自己的弹幕失败；重复举报不重复写记录；管理员处理有审计轨迹。
5. 查询 150 条边界下排序稳定，返回数量与定义后的 `total` 一致。
6. 购买机器人、使用机器人支持券及每日机器人任务均不能虚增弹幕任务进度。
7. AI聊天入口和接口关闭后，三个弹幕接口仍可独立访问并通过权限检查。
