# 1.0 在用逻辑与需求总纲

> 文档状态：基于 `admin`、`h5`、`splay` 三个仓库 `test-old` 分支工作树梳理。  
> 基线日期：2026-08-28。  
> 本文档集只描述和约束 1.0，不代表已经完成代码裁剪、数据迁移或接口下线。

## 1. 文档目的

本目录用于回答四个问题：

1. 1.0 当前到底有哪些可运行逻辑；
2. 哪些能力在目标 1.0 中继续保留，哪些明确排除；
3. 当前代码行为与目标之间有哪些差异、风险和待确认项；
4. 后续裁剪、修复和验收应依据什么边界执行。

每项描述均使用以下标签，避免把推测写成需求：

| 标签 | 含义 |
| --- | --- |
| **现状** | 当前代码已经存在并实际执行的行为 |
| **目标1.0** | 本轮确认需要继续提供的业务能力 |
| **差异** | 现状与目标1.0不一致，后续实现需要处理 |
| **问题** | 已确认缺陷、疑似风险或业务歧义 |
| **建议** | 优化方案，不等同于当前需求；按 P0/P1/P2 排序 |
| **需验证** | 已找到可疑代码路径，但尚需数据、运行环境或业务规则证明影响 |

优先级口径：P0 为资金、安全、重复结算或阻断主链路；P1 为数据口径、业务一致性和明显体验问题；P2 为维护性、可观测性及中长期治理。

## 2. 系统边界与事实来源

### 2.1 三端边界

| 工程 | 职责 | 主要事实来源 |
| --- | --- | --- |
| `h5` | 用户端 Vue 3/Vant 应用；入口、交互、客户端校验和展示口径 | `h5/src/router/routes.ts`、`h5/src/pages/`、`h5/src/apis/` |
| `admin` | 运营管理端 Vue 3/Ant Design Vue；配置、审核、查询和导出 | `admin/src/router/`、`admin/src/pages/`、`admin/src/apis/` |
| `splay` | Go gRPC-Gateway 服务；业务规则、资产事务、模型、缓存和任务 | `splay/apis/`、`splay/services/`、`splay/models/` |

服务端能力混合在 `playlet`、`point`、`user`、`task`、`man` 等服务中。目标1.0的裁剪不能以“删除整个服务”实现，必须以路由、RPC、业务分支、任务和数据依赖为单位处理。

### 2.2 角色

| 角色 | 主要权限 |
| --- | --- |
| 游客 | 浏览公开短剧目录、搜索和免费剧集；不能产生资产或社交写操作 |
| 注册用户 | 登录、观看、收藏、发弹幕、做任务、充值、支持、提现和管理账号 |
| 支持者 | 持有短剧或机器人支持记录，获得直接收益并参与支持等级体系 |
| 团队成员/上级 | 通过最多五层邀请关系参与合规的团队返佣 |
| 合伙人 | 满足支持等级与家庭活跃值条件后参与合伙人分红及领取 |
| 运营人员 | 在管理端维护短剧、机器人、Banner、任务、券和参数 |
| 财务/审核人员 | 查询订单与流水、审核提现、发起出款、处理异常和对账 |
| 系统任务 | 结算收益、到期处理、解冻、统计汇总、支付回查和缓存刷新 |

### 2.3 关键数据域

```text
用户与邀请关系
  ├─ 钱包账户 ── 通用币 / 消费币 / 支持值 / 活跃值 / 冻结资产
  ├─ 内容消费 ── 短剧 / 剧集 / 解锁 / 收藏 / 历史 / 弹幕
  ├─ 支持资产 ── 短剧支持 / 机器人持仓 / 支持券
  ├─ 收益账务 ── 直接收益 / 团队返佣 / 合伙人分红 / 任务奖励
  └─ 法币链路 ── 充值订单 / 支付回调 / 提现 / 出款 / 对账
```

资产和收益的最终事实必须来自服务端账户字段与不可变流水，前端汇总值不能作为结算依据。

## 4. 必须明确区分的同名/近似概念

### 4.1 机器人与 AI 聊天

- **智能收益机器人**：支持、持仓和收益产品，目标1.0保留。当前 wire 名称可能仍为 `AI_INVEST`、`ai_invest`，只作为兼容标识。
- **AI聊天**：聊天角色、会话、消息和模型响应，目标1.0排除。
- 二者只因历史命名包含“AI”而相似，不能按关键词整体删除。

### 4.2 弹幕与聊天

- 弹幕 RPC 位于 `/v1/chat/bullet/comment/*`，但数据对象为剧集时间轴评论，目标1.0保留。
- `/v1/chat/*` 下的角色、会话、消息与 completion 才属于排除的 AI 聊天。

### 4.3 一次性VIP卡与自动续订VIP

- **保留**：一次性购买、激活/排队、到期、剧集解锁、历史订单、已发生且合法的返佣。
- **排除**：自动扣款、订阅续订、订阅状态回调、连续订阅任务、VIP邀请活动。
- 已经成功扣款的历史或在途自动续订权益必须履约至到期，不得因入口下线而提前失效。

### 4.4 普通支持券与机器人支持券

- 普通支持券用于短剧支持；领取接口当前固定关闭，历史券与结算逻辑仍在。
- 机器人支持券通过券码创建机器人持仓，历史 wire 名称包含 `AI`；目标名称为“机器人支持券”。
- 两类券的发放、额度、收益、状态和任务联动不同，不得复用同一规则。

### 4.5 支持等级与 paid VIP

服务端 `User_TipsLevel_VIP` 是支持等级 L1 的历史枚举名，不等于购买的 VIP 卡。文档统一显示为“支持等级 L1”，代码兼容名只在证据或接口清单中出现。

## 5. 全局业务不变量

1. 任何充值、支持、收益、返佣、冻结、解冻、提现和退款必须同时满足：账户变更、业务单据、流水三者金额守恒。
2. 同一支付回调、收益日期、领取周期、券码或提现终态必须幂等；重试不能重复入账。
3. 金额必须由服务端从商品/配置/单据重算；客户端金额仅用于提示或一致性校验。
4. 金额必须是有限、可解析且大于零的定点数；禁止 NaN、无穷、负数和超过精度/额度的值。
5. 所有统计明确时区、半开区间 `[start, end)`、数据源、币种/资产类型和纳入的流水类型。
6. 配置的生效时间、版本和审计人必须可追溯；前端不能复制资金或等级规则作为最终依据。
7. 活动关闭后，核心流程不得继续产生新的活动资格、奖池、赠送、翻倍或活动流水；历史记录只读保留。
8. 禁用/注销用户不得创建新资金动作，但历史账务、KYC和审计记录按合规要求保留。

## 7. 统一验收原则

- 正向、重复请求、并发请求、余额不足、配置缺失、状态过期和外部回调乱序均需覆盖。
- 资金用例至少核对：接口响应、业务单状态、用户账户字段、明细流水、统计聚合。
- 任何“排除”不仅检查页面入口，还检查 API、服务分支、消息队列消费者、定时任务、配置、缓存、通知和统计枚举。
- 历史数据不物理删除；目标版本不再新建排除功能数据，同时可审计地展示历史原始值。
- 前后端显示文案可以中性化，但现有 Proto/数据库枚举在兼容期内保持 wire 值，不在本次文档变更中直接修改。

## 8. 已识别的最高优先级风险

| 优先级 | 风险 | 当前结论 |
| --- | --- | --- |
| P0 | 提现服务端正数、最小/最大金额校验缺失 | 代码路径已确认；负数影响需立即验证并修复 |
| P0 | 全局 `super.password` 可绕过登录密码和支付密码 | 代码路径已确认；生产配置暴露范围需核查 |
| P0 | 合伙人月度领取并发检查月份不一致 | 代码路径已确认；重复领取需并发复现与数据核查 |
| P0 | 短剧支持事务末尾统一扣通用币/加活跃值 | 与分支付方式逻辑冲突；实际资产影响需验证 |
| P1 | 收益总览混入活动/VIP续订等排除类型 | 聚合分组已确认，目标口径需拆分 |
| P1 | 普通支持券领取固定关闭、发放来源不清 | 现状已确认，目标来源待业务决定 |
| P1 | 弹幕总数、审核和任务联动不一致 | 现状已确认，需补审核闭环及真实行为校验 |
| P1 | Banner有效期依赖客户端时间 | 现状已确认，服务端需成为唯一投放口径 |
| P1 | 任务中心存在假任务与废弃字段 | H5及管理端代码已确认 |
| P1 | 硬编码日期/比例与多时区混用 | 多处已确认，需统一业务时区与版本化配置 |
