# 01 机器人

## 1. 业务目标与范围

机器人是以固定支持金额、运行周期和日收益率生成持仓与收益的产品配置。本章聚焦机器人商品、展示、购买限制和生命周期；账户、团队返佣、支持等级与合伙人见 [05-robot-support.md](05-robot-support.md)。

**目标1.0保留：**普通、固定收益、到期冻结/返还、等级机器人、复投机器人和 `AI Invest` 类型的有效能力；用户侧将后者统一称为“智能收益机器人”。

**目标1.0排除：**FlashSale、AI-X/订阅机器人，以及任何依赖活动次数、活动加成或活动奖池的购买和收益分支。历史持仓仍按创建时规则履约并可查询。

角色与入口：

- 用户端：`/robots`、`/robots/detail/:id`、`/robots/refund`、`/robots/levels`、`/robots/aix`；`/robots/aixFlash` 属于排除入口。
- 管理端：机器人列表/编辑、每日收益率配置、持仓及冻结收益查询。
- 系统任务：上下架、每日结算、到期返本、冻结收益解冻。

## 2. 核心对象与状态

| 对象 | 关键字段/状态 | 说明 |
| --- | --- | --- |
| `Robot` | 类型、状态、周期、默认日收益率、支持金额、售价、总额度、单人购买/运行上限、等级门槛、开售时间 | 商品主数据 |
| `RobotDailyIncomeRate` | `robot_id`、第 N 日、收益率 | 指定日覆盖默认收益率 |
| `TipsLedger` | `TipsMethod=ROBOT`、`WAIT/EFFECTIVE/ENDED`、支付方式、金额、收益起止日期 | 用户机器人持仓 |
| `RobotTipsIncomeLedger` | 日期、直接收益、团队返佣、领取/冻结状态 | 每日收益事实 |
| `RobotTipsFreezeLedger` | 冻结、解冻/到期 | 到期返还型与智能收益型的冻结收益 |

历史 `Robot_Type` 枚举数字不能直接解释业务顺序。对外展示应通过明确映射转换，不能根据 enum 数值比较类型。

## 3. 商品展示规则

### 3.1 现状

1. 列表只返回启用且符合上/下架条件的机器人，等级机器人由单独接口展示。
2. `SUBSCRIPTION` 类型在部分结束时间、额度和购买条件中过滤规则不同。
3. 商品可配置默认收益率，也可按运行第 N 日配置覆盖收益率；缺失日回落到默认值。
4. 复投和智能收益机器人的展示销量/托管量会叠加种子值或增长公式，不完全等于真实持仓。
5. 后端返回持仓汇总、收益估算和可用购买信息，H5再按类型分页面呈现。

### 3.2 目标1.0

- 服务端返回 `sale_status`、`can_buy`、`disabled_reason`、真实销量和可选展示销量，客户端不自行推导资金规则。
- 收益率显示必须标注“预计/按规则结算”，并列出运行周期、计息起止和返本方式。
- 历史兼容字段可保留 `AI_INVEST` 名称，但页面、埋点和运营名称使用“智能收益机器人”。
- 排除类型不出现在新购列表；已有持仓只能进入只读详情和履约流程。

## 4. 购买主流程

1. 用户选择机器人，服务端重新读取最新商品与用户状态。
2. 校验用户存在有效邀请上级、商品启用、当前时间不晚于最后购买时间且已到开售时间。
3. 校验用户支持等级不低于商品门槛。
4. 校验商品总额度、用户历史购买次数、当前运行数量和可选持仓额度。
5. 对复投/智能收益类型校验全局与单商品托管限制；活动订阅限制不进入目标1.0。
6. 服务端使用商品价格计算实际扣款，不能信任客户端金额。
7. 在同一事务内扣减通用币、写支出流水、写支持持仓；按原始支持金额增加活跃值并写活跃值流水。
8. 开售时间在未来的兼容持仓为 `WAIT`，否则为 `EFFECTIVE`；返回持仓编号和剩余额度。

### 4.1 购买限制口径

| 限制 | 当前口径 | 目标要求 |
| --- | --- | --- |
| 总额度 | `TotalAmount=-1` 表示不限；其他值按机器人原始支持金额累计 | 明确定义 `0` 是售罄还是不限，禁止前后端歧义 |
| 购买上限 | 历史购买次数 | 明确是否包含已结束、退款和券创建持仓 |
| 运行上限 | 当前有效持仓；现状主要用于复投/智能收益 | 由配置明确适用类型 |
| 持仓额度 | 可受 `TipsParameter` 持仓数影响 | 统一由服务端返回剩余额度 |
| 等级门槛 | 当前支持等级 | 枚举通过等级映射比较，不按数值比较 |
| 托管互斥 | 复投/智能收益存在全局与单品限制 | 产品化配置并给出明确错误原因 |

## 5. 收益与生命周期

### 5.1 计息

- 第 `d` 日收益：`持仓支持金额 × 第d日收益率 ÷ 100`；未配置第 `d` 日时使用默认日收益率。
- 日界线当前跟随服务实例的 `models.Local`/本地时区；目标统一为产品配置的业务时区并使用 `[00:00, 次日00:00)`。
- 每日 12:00 执行并发分片结算。人工领取接口现状也限制在 12:00 后，并包含硬编码日期 `2026-04-28`。
- 标准收益可领取后进入通用币；到期返还/智能收益类的收益可能先进入冻结流水，再由任务解冻。

### 5.2 到期

1. 到达收益结束日期后，持仓从 `EFFECTIVE` 变为 `ENDED`。
2. 所有机器人本金均通过 `TYPE_ROBOT_SUPPORT_INCOME_END_RETURN` 返还通用币。
3. 对应活跃值按创建时增加量反向扣减，并写活跃值流水。
4. 冻结收益到期后由每日任务解冻，写通用币收入流水并更新冻结状态。
5. 重试必须按“持仓 + 结算日/返本类型”幂等，不能重复返本或重复解冻。

### 5.3 等级机器人

- V2 等级机器人当前只在用户“当前等级恰好等于购买等级”时产生收益；旧等级机器人缺少同样复核。
- **待确认：**应按“当前等级不低于购买等级”还是“必须完全相等”结算；用户降级后暂停、终止还是继续履约。

## 6. 资产与流水

| 事件 | 通用币 | 活跃值 | 冻结收益 | 核心流水 |
| --- | ---: | ---: | ---: | --- |
| 现金购买机器人 | `-商品售价` | `+原始支持金额` | 0 | 机器人支持支付、活跃值增加 |
| 机器人支持券创建持仓 | 0 | 0 | 0 | 券状态、机器人支持记录；详见支持券 |
| 每日标准收益领取 | `+收益` | 0 | 0 | 机器人支持收益 |
| 冻结型每日收益 | 0 | 0 | `+收益` | 机器人冻结收益 |
| 冻结收益解冻 | `+收益` | 0 | `-收益` | 解冻收入、冻结记录终态 |
| 到期返本 | `+原始支持金额` | `-创建时活跃值` | 0 | 到期返还、活跃值减少 |

必须分别保存“商品售价”“原始支持金额”“实际扣款”“收益本金”。当前代码允许售价与原始支持金额不同，统计和返本不得混用。

## 7. 异常与边界

- 商品在提交前下架、到达总额度或用户等级下降：购买失败，不产生任何流水。
- 余额不足：购买事务整体失败；不得先写持仓或活跃值。
- 同一用户并发购买：总额度、运行上限和余额应在数据库条件更新/锁内再次校验。
- 每日收益率缺日：回落默认值并记录告警；默认值也缺失时不结算并进入异常队列。
- 结算任务失败：保持可重试状态，按日期幂等补算；不能通过修改“今日收益”覆盖历史事实。
- 商品配置修改：只影响新持仓还是影响存量必须版本化；目标建议存储购买时规则快照。
- 排除类型历史持仓：禁止新购，但继续查询、结算、到期和审计。

## 9. 耦合关系

- 钱包提供扣款、返本、收益和冻结资产。
- 支持等级决定购买门槛并接收活跃值变化。
- 机器人收益产生最多五层团队返佣和合伙人池贡献。
- 机器人支持券创建特殊持仓，但不扣币、不增加活跃值。
- 当前流程混入 AI-X、AI嘉年华、Ramadan、周年庆、补贴等活动钩子；目标1.0必须旁路，详见 [90-excluded-features.md](90-excluded-features.md)。

## 10. 问题、疑问与建议

| 级别 | 类型 | 内容 |
| --- | --- | --- |
| P0 | 需验证 | 并发购买是否能同时突破机器人总额度或单人运行上限；应以并发用例复现并核对锁粒度 |
| P1 | 已确认 | 人工收益领取依赖硬编码日期和12点判断，不利于迁移、补算和多时区运行 |
| P1 | 已确认 | 展示销量使用种子/增长公式，未与真实销量明确区分，可能造成用户误解 |
| P1 | 待确认 | 售价与原始支持金额不同的业务含义，以及返本、活跃值、团队业绩分别采用哪个金额 |
| P1 | 待确认 | 等级机器人应要求“等于”等级还是“不低于”等级 |
| P1 | 建议 | 为每笔持仓保存规则快照：本金、实际支付、日收益率版本、周期、返本和返佣版本 |
| P2 | 建议 | 将兼容 enum 与对外产品名分离，响应增加稳定的 `product_category` |
| P2 | 建议 | 结算任务增加批次号、游标、成功/失败数、补偿入口和对账指标 |

## 11. 验收场景

1. 用户在等级、余额、额度均满足时购买一次，核对扣款、活跃值、持仓和两类流水金额守恒。
2. 余额不足、未绑定邀请关系、等级不足、未开售、已下架、售罄、超过购买/运行上限均失败且无资产变化。
3. 两个请求并发争抢最后一个额度，只允许一个成功。
4. 配置部分日收益率后，逐日核对覆盖值与默认值回落；同一天重跑不重复结算。
5. 到期只返还一次本金、只回退一次活跃值；冻结收益只解冻一次。
6. 排除类型不在新购列表，但其历史持仓仍能查详情、结算和到期。
7. `AI_INVEST` wire 值保持兼容，用户端只显示“智能收益机器人”。
8. 所有机器人收益在 [07-income-statistics.md](07-income-statistics.md) 中归入机器人直接收益或机器人团队返佣，不进入活动收入。
