# 09 支持券

## 1. 业务目标与严格分型

目标1.0存在两种不可混同的券：

| 类型 | 用途 | 目标状态 | 历史兼容名称 |
| --- | --- | --- | --- |
| 普通短剧支持券 | 免扣币创建指定金额的短剧支持并在限定天数产生收益 | 历史、配置和结算保留；新发放来源待确认 | `SupportCoupon` |
| 机器人支持券 | 通过券码为符合关系的新用户创建机器人持仓 | 保留 | “AI礼券”、`RobotCoupon`、部分接口文案“AI券” |

双倍券、充值赠送券、活动兑换券不属于本章保留范围，见 [90-excluded-features.md](90-excluded-features.md)。

用户入口：`/coupons`（普通券历史/状态）、`/aiCoupons`（目标改名“机器人支持券”）。管理端维护券规则、发放、券码和统计。

## 2. 普通短剧支持券

### 2.1 配置

`SupportCoupon` 包含语言、名称/说明、券面支持金额、可使用小时数、收益天数、按持有分钟配置的附加收益阶梯、在线/离线状态及发放/使用统计。管理端当前按语言维护，并有只允许一个在线规则的业务校验。

目标配置要求：

- 金额、收益天数、有效小时和阶梯必须为合法正值，阶梯区间连续且不重叠；
- 上线前固定规则版本，已发券保存快照，不受后续编辑影响；
- 统计区分发放、领取、使用、过期和产生收益；
- 删除已有用户券的规则时只能下线，不能硬删除。

### 2.2 发放/领取现状

- `GetAvailableSupportCoupon` 在函数开头使用固定 `if true` 返回空列表，注释为 2025-10-10 停止自动领取。
- `ReceiveSupportCoupon` 同样固定拒绝。
- 被短路的旧逻辑要求用户存在至少一条 `UserPlan`，每个用户历史上只能有一张普通支持券，并选择当前语言在线规则。
- 管理服务仍注册 `coupon:support` 消费者；`supportCouponJob` 等待VIP完成后检查首条 `UserPlan` 发券。
- 服务启动还可读取 `support_coupon.user_ids` 并对指定用户调用同一任务。
- 用户历史列表、券状态和到期处理仍保留。

### 2.3 目标1.0差异

自动续订VIP和活动被排除，因此“有任意VIP计划即自动发券”不能继续作为默认规则。目标暂定：

1. 保留历史券查询、使用中持仓结算和到期；
2. 用户自助领取保持关闭，直到业务确认新发放来源；
3. `coupon:support` 和启动指定用户发券任务默认关闭，避免后台继续依赖VIP计划发新券；
4. 若未来保留运营人工发放，需独立权限、名单、原因、批次和审计，不得复用活动或VIP购买事件。

**待业务确认：**普通券未来是完全停止新发、仅运营定向发放，还是由某个保留任务发放。

### 2.4 使用与收益

1. 用户选择可支持短剧并提交用户券ID。
2. 服务端校验券属于本人、`UNUSED`、当前时间早于 `ExpiredAt`、短剧支持额度足够，且券面额与本次支持总额完全相等。
3. 在事务内以条件更新将券改为 `USED`，创建短剧 `TipsLedger`；不扣通用币/支持值，不增加活跃值。
4. 每日收益：`券面额 × 短剧日收益率 ÷100 × 券附加比例 ÷100`。
5. 附加比例按实际持有分钟落阶梯；收益结束不晚于券配置 `IncomeDays`。
6. 普通券支持不产生五层团队返佣。

状态机：`UNUSED --使用--> USED`；`UNUSED --过期任务/查询时校验--> EXPIRED`。`USED` 后即使底层支持结束也不恢复为可用。

## 3. 机器人支持券

### 3.1 规则与发放

`RobotCouponRule` 关联指定机器人，配置名称、券有效期、收益周期和自动发放条件；`RobotCouponCode` 表示具体券码；`RobotCouponSendStat` 保存发券人发送、使用和复投统计。

现状支持：

- 管理端按用户ID列表或支持等级批量发放，每个目标用户可生成多张码；单批可生成很大数量（代码按最多约150,000条切片处理）。
- 每日 01:00 `autoGrantRobotCoupon` 可按支持等级自动发放。
- 一组券码归属于 `parent_user_id`，实际使用者可为其1–5层团队成员。
- 列表按规则聚合，仅为每个规则返回最多5个样例券码和总可用数。

目标要求：发放批次必须有规则快照、目标条件、预计数量、实际成功/跳过/失败数、操作人和幂等键。用户侧名称统一“机器人支持券”，wire 名称暂不改。

### 3.2 核券

`CheckRobotCoupon` 根据券码和 `UNUSED` 状态返回名称、周期、收益周期、邀请链接、到期时间及预计收益。

现状预计收益只遍历已配置的逐日收益率记录；缺失日期没有正确补默认收益，可能低估。目标统一复用机器人结算规则计算预估，并标识仅供参考。

### 3.3 使用条件与流程

1. 使用人不得存在任何历史 `TipsLedger`；这比“没有有效持仓”更严格。
2. 券码存在，状态为 `UNUSED`，规则和目标机器人有效，服务端当前时间早于显式 `ExpireAt`。
3. 已有邀请链时，发券人必须位于前1–5层；无邀请链时，现状会尝试自动绑定为发券人的下级。
4. 事务内以 `WHERE status=UNUSED` 原子更新券为 `USED`，记录使用人和时间，增加发券人使用统计。
5. 创建名义金额50、支付方式为支持券的机器人有效持仓；不扣通用币，不增加活跃值。
6. 更新支持任务。当前还会自动填满弹幕任务，应在目标1.0移除，见 [02-barrage.md](02-barrage.md)。

### 3.4 到期与复投

- 未使用券由每分钟 `checkRobotCouponExpire` 改为 `EXPIRED`。
- 核券和使用代码主要检查状态，未在所有路径实时比较 `ExpireAt`；任务延迟窗口内可能使用已过期券，需修复为“请求时校验 + 定时清理”。
- 券使用后的复投/提现转化字段与机器人收益流程耦合，目标只保留经确认的基础复投规则，活动转化排除。
- 券创建持仓没有现金本金来源，到期不得按普通现金持仓返还50通用币，除非业务明确以赠送流水先入账。

## 4. 资产与流水

| 事件 | 钱包变化 | 券/持仓变化 | 收益/返佣 |
| --- | --- | --- | --- |
| 普通券发放 | 0 | 创建 `UNUSED` 用户券 | 0 |
| 普通券支持 | 0 | 券 `USED`，创建短剧支持 | 有直接收益，无团队返佣 |
| 普通券过期 | 0 | `UNUSED→EXPIRED` | 0 |
| 机器人券发放 | 0 | 创建归属发券人的券码 | 0 |
| 机器人券使用 | 0 | 原子 `USED`，创建特殊机器人持仓 | 有机器人直接收益；团队返佣是否有需明确，建议无 |
| 机器人券过期 | 0 | `UNUSED→EXPIRED` | 0 |

所有券本身不是钱包余额；页面不可把券面额计入总资产。

## 5. 异常与边界

- 重复使用同一券码：只有第一个条件更新成功，后续返回已使用。
- 同一用户并发使用两张机器人券：现状“是否有TipsLedger”在事务外，可能两张同时通过；需用户级锁或唯一首持仓约束。
- 规则下线：已发未过期券是否继续有效需配置；默认建议按发放快照履约。
- 发券人被禁用/注销：历史券可审计；未用券是否失效由规则决定。
- 自动绑定邀请关系是高影响写操作，目标应在核券页明确展示并由用户确认，且复用统一邀请权限判断。
- 大批量发券需异步批次、限量和回滚/撤销策略，不能在单请求中无上限生成。

## 7. 问题、疑问与建议

| 级别 | 类型 | 内容 |
| --- | --- | --- |
| P0 | 需验证 | 同一新用户并发使用不同机器人券可能都通过“无历史持仓”检查 |
| P1 | 已确认 | 普通券获取/领取固定关闭，但后台VIP计划发券消费者和启动任务仍存在 |
| P1 | 已确认 | 机器人券核券/使用未在所有路径实时比较 `ExpireAt`，依赖分钟任务更新状态 |
| P1 | 已确认 | 机器人券预计收益缺失默认收益率补齐，可能低估 |
| P1 | 已确认 | 发放 `IssuedCount` 更接近成功用户数，单用户多张时不等于实际券码数 |
| P1 | 需验证 | 邀请权限字段 `IsInviterFansDisabled` 命名/判断方向异常，自动绑定可能错误拒绝或放行 |
| P1 | 待确认 | 普通券未来发放来源、机器人券是否产生团队返佣及是否返名义本金 |
| P2 | 建议 | 建立统一券批次、规则快照、状态机和请求时过期校验，但保持两类券独立领域规则 |

## 8. 验收场景

1. 普通券领取保持关闭且后台不再因VIP事件自动发新券；历史券可列表和结算。
2. 普通券精确金额支持、分钟阶梯、收益天数、无活跃值、无团队返佣逐项正确。
3. 机器人券手工/自动发放批次统计中“用户数、券码数、成功/失败”一致。
4. 核券预估覆盖每个收益日，缺日使用机器人默认收益率。
5. 到期秒后即使定时任务尚未运行也不可使用；同一码并发只成功一次。
6. 同一新用户并发使用两张码只允许一张创建首持仓。
7. 使用券不扣通用币、不增加活跃值、不自动完成弹幕任务，也不凭空返还本金。
8. H5显示“机器人支持券”，旧 API/enum 保持兼容。
