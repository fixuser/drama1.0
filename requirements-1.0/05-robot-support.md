# 05 机器人支持、持仓、团队等级、合伙人与返佣

## 1. 业务目标与范围

本章描述机器人支持产生的持仓、活跃值、支持等级、团队五层返佣、合伙人资格及分红领取。机器人商品和产品生命周期见 [01-robot.md](01-robot.md)，钱包记账见 [06-wallet.md](06-wallet.md)。

目标1.0保留：

- 通用币购买机器人、机器人支持券创建持仓；
- 持仓列表、详情、收益、冻结收益、到期返本；
- 支持等级 L0–L7、当前等级和历史最高等级；
- 最多五层机器人收益返佣；
- 合伙人月度资格、预估、账单和领取；
- 基础合伙人池规则。

排除：FlashSale/AI-X订阅、升级补贴、周年庆加成、VIP邀请、`treasure_plan`、`super_carnival`、Ramadan及其他活动产生的等级、池子或返佣加成。

## 2. 角色与入口

- 用户：`/robots/*` 查看和购买机器人；`/wallet` 查看资产；`/income` 查看收益。
- 团队用户：`/vote/levels`、`/fans/*`、`/family/*` 查看支持等级、团队成员与支持贡献。
- 合伙人：`/family` 查看当月预估、上月可领和领取记录。
- 运营：配置机器人、支持参数、每日收益率；查询持仓、团队和合伙人流水。
- 任务：每日结算、到期返本、冻结解冻、等级刷新、合伙人统计。

H5 `Family` 当前混有VIP、支付和活动文案/演示数据；目标页面只能显示本章保留数据。

## 3. 机器人支持与持仓

### 3.1 现金支持

1. 服务端按机器人售价扣通用币。
2. 以机器人原始支持金额创建 `TipsLedger(TipsMethod=ROBOT)`。
3. 按原始支持金额增加活跃值，记录活跃值流水。
4. 到期将原始支持金额返还通用币，并回退创建时活跃值。
5. 每日直接收益按购买时规则或当日配置结算；返佣另记。

售价、原始支持金额和收益本金当前可以不同。目标必须在持仓上保存三者及其规则版本，并明确每个统计字段采用哪个值。

### 3.2 机器人支持券

- 券创建固定 50 通用币名义支持持仓，不实际扣通用币，也不增加活跃值。
- 券码原子从 `UNUSED` 改为 `USED`，记录实际使用人和上级发券人。
- 只允许从未有过任何 `TipsLedger` 的用户使用；邀请关系需为发券人的1–5层，未绑定用户可能自动绑定。
- 收益周期来自发券规则；到期处理必须识别券持仓，避免凭空返还未支付本金。

券细节见 [09-support-coupon.md](09-support-coupon.md)。

## 4. 支持等级

### 4.1 枚举兼容

`User_TipsLevel` 的数字顺序与业务等级不一致：历史 `VIP` 表示支持等级 L1，不等于付费VIP；`ONE` 至 `SIX` 对应 L2–L7。所有比较必须通过显式 `rank(level)`，禁止比较 enum 数值。

### 4.2 当前门槛

| 展示等级 | 兼容枚举 | 个人活跃值 | 直推且等级≥L2人数 | 1–5层等级≥L2总人数 |
| --- | --- | ---: | ---: | ---: |
| L0 | `FREE` | 0 | 0 | 0 |
| L1 | `VIP` | 0 | 0 | 0 |
| L2 | `ONE` | 50 | 0 | 0 |
| L3 | `TWO` | 200 | 3 | 0 |
| L4 | `THREE` | 1,200 | 10 | 60 |
| L5 | `FOUR` | 7,000 | 20 | 350 |
| L6 | `FIVE` | 40,000 | 35 | 2,000 |
| L7 | `SIX` | 300,000 | 50 | 10,000 |

L2 在 2026-01-30 后还要求个人活跃值达到50且存在有效通用币持仓；更早用户有历史兼容分支。这个硬编码日期应迁移为规则版本，不应继续散落在计算中。

### 4.3 升降级

- 当前等级会随个人活跃值、有效持仓和团队条件变化而升降。
- 历史最高等级单独保留，不因降级回退。
- 增量任务按近期持仓/活跃值变化扫描用户及上级链，另有 L2 漏升兜底任务。
- 机器人收益、购买门槛和团队返佣通常读取当前等级；历史账单应保存结算时等级。

**差异：**H5 `h5/src/pages/Vote/config.ts` 复制了上述阈值，并把直推L2人数命名为 `vip`。目标以服务端配置/响应为唯一规则，前端只渲染。

## 5. 五层机器人收益返佣

1. 每日机器人直接收益结算后，沿用户邀请链最多五层寻找上级。
2. 等级机器人等特殊类型可被排除返佣；目标需配置化列出适用类型。
3. 每层按当前支持等级对应比例计算差额，不重复发放下层已占比例。
4. 收益记录保存：来源持仓、来源用户、受益用户、层级、收益基数、等级、比例版本和日期。
5. 普通用户直接收益失败时不得先发团队返佣；返佣失败不应回滚已合法产生的直接收益，但须进入可重试异常账。

建议唯一键：`(source_tips_ledger_id, business_date, beneficiary_user_id, rebate_type)`。

## 6. 合伙人体系

### 6.1 资格

合伙人分红现状从硬编码时间 `2026-06-12 10:00` 开始计算。用户同时满足：

1. 当前支持等级至少 L4（兼容 enum `THREE`）；
2. 当月家庭活跃值达到对应合伙人门槛。

| 合伙人等级 | 当月家庭活跃值门槛 | 代码分配系数 |
| --- | ---: | ---: |
| Bronze | 5,000 | 0.3 |
| Silver | 50,000 | 0.5 |
| Gold | 500,000 | 0.7 |
| Sultan | 1,500,000 | 1.0 |
| Envoy | 5,000,000 | 1.0 |

“代码分配系数”由 `GetPartnerRate` 直接用于 `合伙人池 × 系数`，并未再次除以100；运营文案如将其解释为百分比会产生数量级歧义，必须在上线前确认。

### 6.2 池与差额

- 通用币短剧支持和机器人支持按支持金额的5%进入基础合伙人池。
- 周年庆分支可提升至10%，目标1.0排除，任何活动配置不得改变基础5%。
- 沿上级1–5层按合伙人等级的系数差额分配。
- 每条记录保存来源层级/用户、支持金额、池金额、支持等级、合伙人等级、本人系数、上一有效系数、差额和收益到期月。

### 6.3 预估与领取

- 当月展示预估，不可领取。
- 上月结算在当月第5日后可领取；领取后通用币增加并写合伙人分红流水。
- 领取必须以“用户 + 收益月份”唯一且原子完成，不能只依赖分布式锁。

### 6.4 P0 并发风险

`ReceivePartnerRebate` 在加锁前检查“当前月是否已领取”，加锁后却检查“上一个月是否已领取”。月份口径不一致，且已核对模型未见明确的用户/月唯一键。

- **代码路径已确认。**
- **重复领取影响需验证。**使用两并发请求领取同一月份，并核对领取记录与钱包流水。
- 修复要求：锁前后都以目标收益月查询；数据库唯一键兜底；入账与领取状态同一事务；重复请求返回原结果。

## 7. 资产、流水与统计

| 事件 | 通用币 | 活跃值 | 流水/记录 |
| --- | ---: | ---: | --- |
| 现金机器人支持 | `-售价` | `+原始支持额` | 支持支付、活跃值增加、持仓 |
| 券机器人支持 | 0 | 0 | 券使用、特殊持仓 |
| 机器人直接收益 | `+直接收益` 或进入冻结 | 0 | 机器人收益/冻结收益 |
| 五层返佣 | `+返佣` | 0 | 机器人团队返佣 |
| 合伙人领取 | `+已结算分红` | 0 | 合伙人分红、月领取记录 |
| 到期返本 | `+原始支持额` | `-原始活跃值` | 到期返还、活跃值回退 |

机器人券持仓不得产生现金本金返还，除非规则明确有独立赠送本金并且存在赠送流水。所有类型在 [07-income-statistics.md](07-income-statistics.md) 中分别归类。

## 10. 验收场景

1. 各等级在门槛前后一单位正确升降，enum数值顺序不影响比较；H5只展示服务端条件。
2. 机器人现金支持、券支持、直接收益、五层返佣和到期返本分别守恒。
3. 同一来源和业务日重跑结算不重复发直接收益或五层返佣。
4. 合伙人五个门槛、L4前置条件、基础5%池和差额系数逐项核对。
5. 两个并发领取同一月份只有一笔入账；第5日前不可领取，当月仅展示预估。
6. 周年庆或其他活动配置存在时，目标1.0仍使用基础5%，不生成活动加成流水。
7. paid VIP购买/到期不直接改变支持等级，历史枚举 `TipsLevel_VIP` 只显示为L1。
