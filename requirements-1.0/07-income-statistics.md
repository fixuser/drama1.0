# 07 收益统计

## 1. 业务目标与入口

收益统计将已入账的直接收益、团队返佣、任务奖励和合伙人分红按日、周、月和累计展示，并提供曲线、月账单与年度汇总。用户入口为 `/income` 及钱包总览；运营端使用用户统计、收入排行榜、资金 rollup 与对账页面。

统计只解释已经由业务和钱包确认的事实，不得成为再次入账的依据。

## 2. 统计维度与时间边界

### 2.1 目标口径

所有接口必须返回 `timezone`、`start_at`、`end_at`、`generated_at` 和数据是否包含历史回填。统一使用半开区间 `[start_at, end_at)`：

| 维度 | 边界 |
| --- | --- |
| 日 | 业务时区当日 00:00 至次日 00:00 |
| 周 | 业务确认的周起始日 00:00 至下周起始日 00:00 |
| 月 | 自然月首日 00:00 至下月首日 00:00 |
| 年 | 自然年首日 00:00 至次年首日 00:00 |
| 累计 | 用户首笔目标收益入账时间至查询时刻 |

当前代码混用 `time.Local`、请求/服务器 location 和 `Asia/Jakarta`，周边界也有周一与周日两套实现。业务时区和周起始日尚未确认；在确认前不得以客户端本地时间作为财务口径。

### 2.2 历史数据

- 目标1.0上线日前的合法保留收益继续纳入累计和对应历史月份。
- 排除功能的历史收益保留原始账务和审计页面，但不进入“1.0业务收益”总额。
- 如需展示“历史全口径总收入”，必须使用独立字段/筛选，不能与目标1.0口径同名。
- 回填和重算必须记录版本、批次、时间范围和差异，不覆写原始流水。

## 3. 收益分类

| 目标分类 | 纳入流水/来源 | 排除或单列 |
| --- | --- | --- |
| 短剧直接收益 | 短剧支持持仓每日收益 | 普通券按券收益仍归此类但标记来源 |
| 短剧团队返佣 | 短剧支持最多五层返佣 | 活动翻倍/补贴 |
| 机器人直接收益 | 机器人每日收益、冻结收益实际解冻入账 | 本金返还不算收益 |
| 机器人团队返佣 | 机器人最多五层返佣 | 活动机器人加成 |
| 合伙人分红 | 已领取入账的基础合伙人分红 | 当月预估不计已收入；周年庆加成排除 |
| 剧集返佣 | 单集通用币支付产生并已解冻的合法返佣 | 消费币部分不返佣 |
| 一次性VIP返佣 | 一次性VIP卡的合法历史/新购返佣 | 自动续订和VIP邀请活动返佣 |
| 任务奖励 | 目标1.0保留任务领取 | 活动、版权、连续订阅任务 |
| 其他调整 | 经审计的人工补账/冲正，必须单列 | 不得把未知枚举默认塞入收益 |

充值本金、充值赠送、本金返还、兑换、提现退回和消费退款不是收益。

## 4. 当前实现与数据源

### 4.1 收益总览

`GetIncomeOverview` 当前查询 `PointLedger` 的 `TypeGroup_INCOME` 且资产类型为通用币：

- 今日使用实时流水；周从周一开始；月从月初开始；累计不限制起点。
- 缓存到当日午夜，检测今日值变化时主动更新。
- 收入超过百分比通过Redis统计任务计算。

**问题：**`TypeGroup_INCOME` 包含任务、活动、合伙人及多种历史奖励，未按目标1.0净化，因此活动/VIP续订等可能混入总览。

### 4.2 收益详情与曲线

`GetIncomeDetails` 将收入拆为支持、支持返佣、VIP返佣、剧集返佣、活动和其他。`GetIncomeDistributed` 从 `UserStatsDetail` 汇总支持、粉丝支持、VIP、剧集、活动和其他，当前只接受日/周/月，不支持年。

**差异：**目标需要日/周/月/累计曲线及年度汇总；现有曲线分类仍显式包含活动。

### 4.3 月账单与年度汇总

- `GetIncomeMonthBill` 返回上月/本月/下月导航，但查询未像总览/年度接口一样过滤 `point_type`，可能把消费币流水混入。
- `GetIncomeTotalBill` 按年、月、类型聚合并过滤通用币，可作为年度汇总基础。
- `incomeLedgerTypeGroup` 映射未完整覆盖剧集返佣、合伙人分红等类型，可能在不同接口落入不同分类。

### 4.4 预聚合

`UserStatsDetail` 和 rollup 表用于历史统计，管理服务每分钟增量聚合 point ledger、订单/提现和 tips ledger，每日进行全量对账。今日值还会由实时查询替换，存在实时与快照双源。

目标要求记录数据源优先级：已封账历史使用已对账快照，当日使用流水增量；封账后按差异调整而不是静默改历史。

## 5. 计算规则

### 5.1 总额

`期间收益 = Σ 目标收益流水正向金额 + Σ 目标冲正流水金额`

不按业务单上的“预计收益”求和。冻结收益只在实际解冻进入可用通用币时计入“已入账收益”；可另显示“待解冻收益”。

### 5.2 曲线

- 日曲线：按小时或业务要求粒度汇总，但所有点之和必须等于日总额。
- 周/月曲线：按自然日汇总，缺失日期补零，不能省略导致前端错位。
- 累计曲线：按月或可配置粒度返回，并附起止时间。
- 当日未结束点标识 `provisional=true`；封账后为 `final=true`。

### 5.3 月账单

月账单包含期初/期末、各收益分类、待解冻增加/解冻、冲正和总额；只统计通用币收益。支持按业务类型展开到流水。

### 5.4 超过用户百分比

该指标是展示性排名，不是资金事实：

- 明确样本用户范围、统计时间窗和更新时间；
- 样本不足时返回空而非伪造百分比；
- Redis缓存失效不能影响收益金额。

## 7. 异常、对账和缓存

- 未知流水类型：进入“待归类”监控，不默认算入其他收益。
- 实时流水与聚合表不一致：金额展示采用可追溯主源并标记数据延迟，触发差异告警。
- 跨午夜查询：在同一请求内固定 `as_of`，避免各卡片使用不同日期。
- 缓存键必须包含用户、时区、范围和口径版本；活动下线后主动失效旧缓存。
- 退款/冲正跨月：在发生月记录负向调整，并能追溯原始收益月；是否追溯重开历史账单由财务规则决定。

## 9. 验收场景

1. 在业务时区日/周/月/年边界前后入账，逐项核对半开区间，不重不漏。
2. 同一组流水在总览、详情、曲线、月账单和年度汇总中的总额与分类一致。
3. 活动、充值赠送、自动续订、VIP邀请和本金返还均不进入1.0收益。
4. 消费币任务/支出不会混入通用币月账单；冻结收益只在解冻时计已入账。
5. 当日实时值与封账后快照一致；rollup重跑不重复，差异可追溯。
6. 缺失日期补零，曲线点之和等于卡片总额；累计包含所有合法历史收益。
7. 时区切换、夏令时（如未来采用有DST地区）、跨月冲正和缓存失效均有自动化用例。
