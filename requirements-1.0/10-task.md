# 10 任务

## 1. 业务目标与范围

任务模块通过可验证的用户行为记录进度并发放一次性或周期奖励。目标1.0保留新手、每日、超级和支持类任务，以及必要的视频任务；排除版权包、活动、自动续订和连续订阅任务。

用户入口为 `/mission`，管理端包括任务配置和任务视频配置。H5还会从Banner和其他页面跳转任务，所有入口需使用同一任务状态。

## 2. 任务分类与重复规则

| 维度 | 当前枚举 | 目标解释 |
| --- | --- | --- |
| 类型 | `NEW` | 新手/一次性任务 |
| 类型 | `DAILY` | 每日任务 |
| 类型 | `SUPER` | 超级任务；不等同于活动或任务包 |
| 类型 | `TIPS` | 支持类任务 |
| 重复 | `NONE` | 用户生命周期仅一次 |
| 重复 | `DAILY` | 业务日重置 |
| 重复 | `WEEKLY` | 业务周重置 |

`TaskPlan/UserTaskPlan` 是付费任务包模型，不等于 `SUPER` 任务；是否属于目标1.0尚未确认，本文不将其默认纳入保留能力。版权包即使与任务服务共存也明确排除。

## 3. 对象与状态机

| 对象 | 关键字段 |
| --- | --- |
| `Task` | 类型、名称、链接、奖励、目标次数 `Base`、奖励资产类型、状态、重复规则 |
| `UserTask` | 用户、任务、业务日期、已完成次数、完成标记、`VALID/COMPLETED/RECEIVED/BOOKED`、完成/领取时间 |
| 任务视频 | 任务名称、视频地址/供应商信息、状态和排序 |

目标状态机：

```text
VALID --业务事件累计到Base--> COMPLETED --领取/自动发放--> RECEIVED
VALID --周期结束未完成--> EXPIRED（现有枚举不足时可派生）
BOOKED --到预约业务日--> VALID
```

一次性任务应使用生命周期唯一约束；日/周任务分别使用 `(user_id, task_id, period_start)` 唯一约束。当前模型唯一键使用 `date`，周任务如何复用需验证。

## 4. 列表规则

### 4.1 现状

- H5主要调用 `ListTask` 老接口；服务端同时存在 `ListUserTaskV2`，两套过滤和发奖行为不同。
- 启用任务全局缓存约60秒，管理端修改时有失效机制。
- 支持类任务只对已经首次支持或存在有效支持持仓的用户展示。
- 新手任务只对 2025-08-08 之后注册用户显示，是硬编码迁移日期。
- `ListTask` 特殊处理 `SUB_VIP` 与 `CONTINUE_SUB_VIP_30`。
- V2过滤实名、分享、看短剧、广告等任务，并仍查询有效版权包，说明边界尚未完成拆分。
- H5会注入ID `999999` 的 `WebsiteShortPro` 假任务，不来自后端。

### 4.2 目标1.0

- 收敛为一套任务列表/进度/领取语义，旧接口仅兼容代理，不能各自计算状态。
- 服务端返回可见、不可见原因、当前进度、目标、周期起止、奖励和是否可领。
- 去除H5假任务；所有显示项必须有服务端任务ID和审计配置。
- 一次性VIP购买任务如保留，只能指“完成一次一次性VIP卡购买”，应与 `CONTINUE_SUB_VIP_30` 分离；后者排除。
- 注册日期兼容应配置为任务生效版本，而非代码常量。

## 5. 进度来源

### 5.1 自动业务事件

任务进度应由已完成且可审计的领域事件推进：

- 注册/安全设置/加入官方渠道等新手行为；
- 成功发送真实弹幕；
- 短剧支持或机器人支持成功；
- 一次性VIP订单成功（如确认保留该任务）；
- 充值只能按实付原始金额推进，不按赠送金额；
- 视频任务在满足有效观看规则后推进。

### 5.2 手动更新接口

当前 `UpdateTaskProgress` 只允许白名单任务由客户端推进，其余由业务服务调用。目标要求：客户端只提交可验证事件凭证，不得直接指定任意任务ID加进度；服务端按事件映射任务。

### 5.3 已确认的不真实进度

- 创建机器人支持和使用机器人券时会循环推进 `BARRAGE` 任务到满。
- 每日12:00 `checkRobotBarrageTask` 自动完成弹幕任务。
- H5假任务的完成状态只能由页面自己模拟。

以上路径目标1.0全部移除。奖励机器人持有者应定义独立任务，不能伪造弹幕行为。

## 6. 奖励领取与资产

### 6.1 现状差异

- V2新手任务完成后可直接增加消费币并写任务流水。
- 老 `GetTaskIncome` 采用完成后手动领取，按 `IncomePointType` 增加资产并将状态改为已领取。
- 支持用户完成全部每日任务后，会立即触发短剧支持当日收益结算。

### 6.2 目标规则

1. 每个任务明确自动发放或手动领取，不能由接口版本决定。
2. 领取在用户资产锁和数据库事务内执行，条件更新 `COMPLETED→RECEIVED`。
3. 奖励金额和资产类型读取任务规则快照；客户端不能传金额。
4. 写任务奖励流水，关联 `user_task_id` 和规则版本。
5. 重复领取返回原领取结果，不再次入账。
6. 支持收益是否依赖完成全部每日任务需业务确认；若保留，任务周期、补做和未完成后果必须明确。

## 7. 视频任务

- 管理端按任务配置视频素材；用户接口获取可看视频URL。
- 当前特定视频接口调用会直接更新观看报告任务。
- 目标应记录开始、有效观看时长、完成和防刷信号；仅获取URL不能等于完成观看。
- 视频失效、供应商失败或任务下线时不扣用户进度，并有替换素材能力。

## 8. 管理端配置

- 配置任务名称、类型、重复周期、目标次数、奖励资产/金额、起止时间、进度事件和自动/手动发放。
- 修改已被用户领取的任务只能创建新版本，不能追溯改变历史奖励。
- 当前管理端仍提交 `is_tips_task`、`tips_task_base`，而服务端模型字段已注释废弃；目标删除旧字段，统一使用 `Type=TIPS` 与 `Base`。
- 管理端任务名称枚举必须隐藏所有排除的版权、活动、连续订阅任务。

## 9. 异常、边界和缓存

- 并发同一事件：用事件ID/业务单号去重，进度最多增加一次。
- 达标后多次事件：进度封顶 `Base`，不重复触发发奖。
- 日/周边界：固定业务时区与周期起点；请求处理中跨午夜使用同一 `as_of`。
- 任务下线：已完成未领取是否可领取需配置，默认保障已完成权益。
- 配置缓存：管理端发布后主动失效；旧规则快照仍用于已有 `UserTask`。
- 外部行为无法验证：不能仅凭客户端按钮点击发奖励。

## 12. 验收场景

1. 新手、日、周、支持和超级任务在周期边界正确创建、累计、完成和重置。
2. 相同业务事件重复/并发上报只增加一次，进度不超过 `Base`。
3. 自动发奖和手动领取按配置执行，重复领取不重复入账，流水资产类型正确。
4. 真实弹幕才推进弹幕任务；机器人支持、券使用和定时任务不能代替。
5. H5列表与管理配置一致，无ID 999999或其他前端假数据。
6. 版权包、活动、自动续订和连续订阅任务不展示、不推进、不发奖。
7. 一次性VIP任务（如确认）只由一次性订单完成事件推进，不接受自动续订回调。
8. 完成全部每日任务触发短剧收益的规则（如确认）重试幂等且不会漏结/重复结。
